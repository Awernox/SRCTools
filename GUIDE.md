# SRCTools — руководство

Одна страница: как пользоваться, как настроить и как выпустить релиз.
Всё остальное (`README.md`, `ARCHITECTURE.md`) — для разработки и в установщик
не попадает.

---

## 1. Установка

**Пользователю не нужны Git, Node.js, Rust и исходный код.**

1. Скачать `SRCTools-Setup.exe` со страницы релиза на GitHub.
2. Запустить, выбрать язык, установить.
3. Ярлыки появятся на рабочем столе и в меню «Пуск».

Портативный вариант: `SRCTools.exe` рядом с установщиком — работает без
установки, настройки хранит там же, где и установленная версия.

Данные лежат в `%APPDATA%\com.srctools.app`: база `srctools.db` (кэш, история,
настройки) и логи `srctools.log`. Ключи в базу не пишутся никогда.

## 2. Первый запуск

### API-ключ Speedrun.com

Без него доступны только локальные страницы (история, настройки).

1. Открыть <https://www.speedrun.com/settings/api>.
2. Скопировать ключ.
3. В SRCTools: **Settings → Account → API key**, вставить, нажать сохранить.

Ключ проверяется запросом `GET /profile` до сохранения — неверный ключ не
сохранится. Хранится он в Windows Credential Manager, а не в файле. Обратно
приложение его не читает: после сохранения видна только маска.

### Twitch (необязательно)

Нужен только для проверки видео с Twitch. **Settings → Account → Twitch video
checks**, Client ID и Client Secret из <https://dev.twitch.tv/console/apps>.
Без них видео с Twitch будет со статусом «проверить не удалось» — это не
«удалено».

## 3. Что делает приложение

| Страница | Для чего |
| --- | --- |
| **Dashboard** | Сколько ранов ждёт, что происходило за последнее время |
| **Review Queue** | Очередь на проверку: подтвердить, отклонить, удалить |
| **Fast Review** | По одному рану на весь экран, с горячими клавишами |
| **Games** | Игры, которые вы модерируете; категории, уровни, таблицы |
| **History** | Локальная история ваших действий, экспорт в CSV/JSON |
| **Stats** | Статистика модерации за период |
| **Settings** | Всё ниже |

Горячие клавиши — `?` в любом месте. Командная палитра — `Ctrl+K`.

### Важное правило

Анализ ранов (подозрительное время, новый игрок, проблемы с видео) **никогда не
принимает решение сам**. Он только помечает ран как «стоит посмотреть».
Подтверждение и отклонение — всегда ручное действие.

То же с видео: если провайдер не ответил или упала сеть, статус будет
«проверить не удалось», а не «удалено». Удалённым видео считается только то,
про которое провайдер прямо сказал, что его нет.

## 4. Уведомления о новых ранах

**Settings → Notifications.**

- **Watch for new runs** — фоновая проверка. Работает в Rust, а не в интерфейсе,
  поэтому продолжает работать со свёрнутым окном.
- **Check interval** — 1 с, 3 с, 5 с, 10 с, 30 с, 1 мин, 5 мин. По умолчанию 5 с.
- **Sound** — свой файл через **Custom sound** (mp3, wav, ogg, m4a, flac, до 5 МБ).
  Файл копируется в папку приложения, так что его можно потом переместить или
  удалить. Кнопка сброса возвращает встроенный звук.

Задержка обнаружения при интервале 5 с — примерно 5–10 секунд. Запросы к
Speedrun.com идут с обходом CDN-кэша: без этого их CDN отдаёт ответ пятиминутной
давности, и уведомление приходило бы с задержкой до нескольких минут.

Строка состояния внизу показывает, когда была последняя проверка и что пошло не
так, если что-то пошло не так.

## 5. Discord

### Rich Presence

**Settings → Discord.** Нужен Application ID из
<https://discord.com/developers/applications>.

1. Создать приложение, скопировать **Application ID**.
2. В **Rich Presence → Art Assets** загрузить логотип с именем ровно `srclogo`.
3. Вставить ID в SRCTools и включить.

Отдельно настраивается, что показывать: страницу, число ожидающих ранов, игру,
имя модератора. Последнее по умолчанию выключено — оно показывает ваше имя всем
в списке друзей.

### Webhook в канал

**Settings → Notifications → Discord webhook** (внизу страницы).

1. В Discord: **Настройки канала → Интеграции → Вебхуки → Копировать URL**.
2. Вставить в поле, сохранить. URL уходит в Credential Manager и обратно не
   показывается — только маска. **Test** отправляет проверочное сообщение.

Что отправлять — пять переключателей: новые раны, подтверждённые, отклонённые,
удалённые видео, проблемы с видео. Зелёный — отправляется, серый — нет.

В сообщении об отклонении есть поле **Reason** — та самая причина, которую вы
написали рану и которую видит бегун на Speedrun.com. Работает и при массовом
отклонении. Если причина не записана, поля просто нет: придумывать за вас,
что было сказано бегуну, приложение не станет.

**Games** — фильтр по играм, тоже переключателями.

- **All games** включён (зелёный) — идут все игры, которые вы модерируете.
- **All games** выключён — появляется список ваших игр, по переключателю на
  каждую. Зелёная игра отправляется в канал, серая нет.

Если **All games** выключен и ни одна игра не горит зелёным, в канал не уйдёт
ничего — так и задумано, это видно по списку.

> Пример: писать только про подтверждённые и отклонённые раны в двух играх —
> оставить зелёными **Approved runs** и **Rejected runs**, остальные три
> погасить, выключить **All games** и зажечь *Bhop pro* и *Run pro*.

Сбой Discord никогда не ломает действие модератора: ран уже подтверждён на
Speedrun.com, а про неотправленное сообщение приходит одно предупреждение, а не
по одному на каждый ран.

## 6. Обновления

**Settings → About.**

При запуске SRCTools спрашивает у GitHub Releases последнюю версию и сравнивает
с установленной. Если новее — открывается окно «Доступна новая версия SRCTools» с
обеими версиями и кнопками **Скачать обновление** и **Позже**. Если новее нет —
не показывается ничего.

Кнопка **Проверить обновления** делает то же самое вручную и всегда отвечает:
есть обновление, версия последняя, GitHub недоступен или источник не настроен.

Скачивание открывается в браузере. Приложение ничего не скачивает и не
запускает само — установщик запускает пользователь.

## 7. Выпуск релиза (для разработчика)

### Сборка

```bash
npm install
npm run build:windows
```

Готовое лежит в `src-tauri/target/release/`:

- `bundle/nsis/SRCTools_1.0.0_x64-setup.exe` — установщик;
- `bundle/msi/SRCTools_1.0.0_x64_en-US.msi` — MSI;
- `SRCTools.exe` — портативный.

Проверки перед сборкой:

```bash
npm run typecheck
```

```bash
cd src-tauri && cargo clippy --lib --all-targets && cargo test --lib
```

### Версия

Версия объявлена в трёх местах, которые обязаны совпадать:

| Файл | Поле |
| --- | --- |
| `src-tauri/Cargo.toml` | `version` — **источник истины**, из него `CARGO_PKG_VERSION` |
| `src-tauri/tauri.conf.json` | `version` — из него имена файлов установщика |
| `package.json` | `version` |

Приложение читает только `Cargo.toml` (через `CARGO_PKG_VERSION` →
`StartupReport.version`). Отдельного `version.json` нет намеренно: ещё один файл
с тем же числом — это ещё одно место, где оно разойдётся.

### Источник обновлений

Задан в `src-tauri/Cargo.toml`:

```toml
repository = "https://github.com/Awernox/SRCTools"
```

Приложение читает только эту строку и превращает её в
`api.github.com/repos/Awernox/SRCTools/releases/latest`. Переедет репозиторий —
менять здесь и больше нигде.

### Выпуск

1. Поднять версию во всех трёх файлах.
2. Собрать (`npm run build:windows`).
3. На GitHub: **Releases → Draft a new release**.
4. Тег — `v1.0.0` (префикс `v` необязателен, сравнение его игнорирует).
5. Приложить `SRCTools_1.0.0_x64-setup.exe` и, по желанию, `SRCTools.exe`.
6. В описание — что изменилось: этот текст видно в окне обновления.
7. **Publish release** — не draft и не pre-release, иначе GitHub не отдаст его
   как latest и клиенты обновление не увидят.

Из приложенных файлов выбирается `*setup.exe`, затем `.msi`, затем `.exe`,
затем `.zip`. Если ничего не подошло — кнопка откроет страницу релиза.

Сравнение версий числовое: `1.10.0` новее `1.9.0`. Пре-релиз (`1.1.0-rc.1`) не
считается новее готового `1.1.0`. Нечитаемый тег обновлением не считается
никогда.

## 8. Если что-то не так

| Симптом | Что смотреть |
| --- | --- |
| Уведомления не приходят | **Settings → Notifications**, включён ли watch; строка состояния внизу — последняя проверка и ошибка |
| Пустая очередь | Есть ли ключ; **Only my games** в **Settings → Moderation**; права модератора на игру |
| Видео «проверить не удалось» | Не удалено. Twitch — нужны Client ID/Secret; YouTube — временный отказ провайдера, кнопка перепроверки |
| Webhook молчит | Включён ли **Enable webhook**; горят ли переключатели событий; **All games** выключён и ни одна игра не зелёная — тогда не уйдёт ничего |
| Rich Presence не появился | Discord запущен; Application ID вставлен; ассет назван ровно `srclogo` |
| «Rate limit reached» | **Settings → Moderation → Request budget**, уменьшить частоту |
| Не понятно, что произошло | `%APPDATA%\com.srctools.app\srctools.log` — ключей там нет |

Приложение никуда не отправляет данные, кроме Speedrun.com, Twitch (если
настроен), вашего Discord-вебхука и GitHub при проверке версии.
